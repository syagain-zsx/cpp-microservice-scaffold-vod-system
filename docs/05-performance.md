# 性能基线（M8 起步）

> 目的：先有**可复现的基线**，再谈优化。所有数字都来自本仓库脚本，换机器可重跑。

---

## 1. 测试环境

| 项 | 值 |
| --- | --- |
| 机器 | Docker 容器，Ubuntu 22.04，**2 vCPU** |
| 部署 | 5 个服务 + 网关同机；MySQL/Redis/etcd/RabbitMQ/FastDFS 在 Docker 网络内 |
| 构建 | Debug（`-g -O0`），未做编译优化 |
| 场景 | `POST /HttpService/allVideoList`（读路径：网关 → RPC → video → Redis/MySQL） |
| 工具 | [`scripts/bench.py`](../scripts/bench.py)（Python 线程池，测量端到端延迟） |

> 注意：Debug 构建 + 2 核 + 同机跑全部组件，数字只用于**横向对比**，不代表生产性能。

---

## 2. 结果

| 并发 | 请求数 | QPS | avg (ms) | p50 | p90 | p99 | max |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 20 | 300 | 276 | 69 | 68 | 100 | 145 | 165 |
| 50 | 1000 | 290 | 148 | 155 | 252 | 346 | 366 |

结论：吞吐在 ~280–290 QPS 饱和，继续加并发只增加排队（p50 从 68ms 涨到 155ms）。
瓶颈是**2 个核被网关 + 5 个服务 + 中间件客户端共享**，以及列表接口每次都回源 DB。

### 2.1 优化后：首页列表短缓存（3s）

`SvcData::getMainPageList` 把组装好的 `VideoInfo` 列表用 protobuf 序列化后写入 Redis，
key 为 `cache_main_page_<page>_<count>`，TTL 3 秒；命中直接返回，不再走权限/DB/RPC 下游查询。

| 并发 | 请求数 | QPS（前 → 后） | p50（前 → 后） | p99（前 → 后） |
| --- | --- | --- | --- | --- |
| 20 | 300 | 276 → **765**（+177%） | 68 → **18ms** | 145 → **49ms** |
| 50 | 1000 | 290 → **804**（+177%） | 155 → **47ms** | 346 → **94ms** |

代价：视频上架/下架后最多 3 秒才能在首页看到；测试脚本（`e2e-test.py`）改为轮询等待。


复现：

```bash
./scripts/run-dev.sh start
python3 scripts/bench.py --concurrency 20 --total 300
python3 scripts/bench.py --concurrency 50 --total 1000
```

## 3. 瓶颈分析（读路径）

```text
gateway allVideoList
  → judgePermission：查 URL→角色 + 会话（Redis/MySQL）
  → RPC 到 video
    → 查在线视频 id 列表（MySQL）
    → 按 id 批量取视频详情（Redis 优先，未命中回 DB）
    → 组装 VideoInfo（含用户昵称/头像等）
  → JSON 序列化返回
```

耗时点：
1. **权限校验**每次请求都查（虽然有 Redis 缓存）；
2. **列表 + 详情 + 用户信息**多次查询，未做批量/缓存；
3. Debug 构建无优化；
4. 2 核 CPU 上，网关与子服务的 JSON/protobuf 编解码占比较高。

---

## 4. 可落地的优化项（按收益排序）

| # | 优化 | 预期收益 | 成本 |
| --- | --- | --- | --- |
| 1 | 列表结果整体缓存（如 30s），或缓存「在线视频 id 列表」 | 高（少一次 DB 查询/请求） | 低 |
| 2 | 批量查询用户信息（避免 N+1） | 中高 | 中 |
| 3 | Release 构建（-O2） | 中 | 低 |
| 4 | 权限结果本地缓存（进程内 LRU + Redis） | 中 | 低 |
| 5 | 网关水平扩容（2 实例）+ 压测机分离 | 高 | 中 |
| 6 | MySQL 连接池/索引调优，`EXPLAIN` 慢查询 | 中 | 中 |
| 7 | protobuf JSON 序列化替换为更快实现 | 低 | 中 |

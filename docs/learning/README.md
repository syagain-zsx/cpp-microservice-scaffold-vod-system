# 笺流 · 6 周学习计划

> 面向「要拿这个项目找工作」的人：项目已经能跑、有测试、有文档，但代码不都是你写的。
> 这套计划的目标不是重写一遍，而是让你能 **定位、改造、讲清**。

## 这套计划怎么用

0. **术语看不懂**：先查 [glossary.md](glossary.md)（lease、watch、TTL、DLX、remux、幂等…都有大白话 + 类比）；
1. **先读** [cheatsheet.md](cheatsheet.md)，把环境跑起来（`./scripts/learn-check.sh` 自检）；
2. 按周学习：[week-01](week-01.md) → [week-02](week-02.md) → … → [week-06](week-06.md)；
3. 读完每周先看 [reading-order.md](reading-order.md) 对应章节，再动手；
4. 第 2/4/6 周末做 [checkpoints.md](checkpoints.md) 的 CP1/CP2/CP3；
5. 每周留一份周记（模板在每周文末），6 周后整理成面试素材。

## 时间与节奏

- 每周 **8–10 小时**，建议拆成 3 次 × 2 小时：

| 次 | 做什么 | 时间 |
| --- | --- | --- |
| 读 | 读主线代码 → 画调用链 → 用命令复现 | 45 + 30 + 45 min |
| 改 | 设计小改动 → 编码调试 → 跑验收 | 30 + 60 + 30 min |
| 讲 | 自测面试题 → 录音讲解 → 补漏 + 周记 | 30 + 45 + 45 min |

- 每周固定产出：**1 张调用链图 + 1 个 diff + 1 段录音 + 周记**；
- 时间不够时：**砍范围不砍主线**——优先保住“跑 + 讲”，代码改动可以减量。

## 学习原则

1. **不重写，只做「定位、改造、讲清」**：每次只追一条请求；
2. **先跑再读**：日志是阅读顺序的锚点；
3. **输出驱动**：没有图/diff/录音，等于没学；
4. **允许查资料和 AI，但每个改动都要能解释动机**；
5. **每周开场先不看笔记演示上周内容**（复习比新学重要）。
